# Matches Advanced Inspection

This file consolidates advanced packet inspection matches that operate on raw packet bytes, OS fingerprinting, or complex boolean expressions.

---

# Reference: bpf

## Type
- `match`

## Purpose
Match packets using a Berkeley Packet Filter (BPF) bytecode expression, enabling arbitrary low-level packet matching programmable at filter time.

## Scope
- Tool: `iptables` / `ip6tables`
- Common protocols: any

## Basic syntax
```bash
iptables -A INPUT -m bpf --bytecode "4,40 0 0 12,21 0 1 2048,6 0 0 1,6 0 0 0" -j ACCEPT
```

## Available options / matches
- `--bytecode bytecode_string`

## Use cases by purpose
- `deep-inspection`
- `custom-protocol`
- `hardening`

## Command examples
```bash
# Accept only IPv4 Ethernet frames using raw BPF bytecode
iptables -A INPUT -m bpf --bytecode "4,40 0 0 12,21 0 1 2048,6 0 0 1,6 0 0 0" -j ACCEPT

# Drop traffic matching custom application signature
iptables -A FORWARD -m bpf --bytecode "<compiled_bpf>" -j DROP
```

## Dependencies
- requires kernel BPF support
- bytecodes are typically generated by `pcap-filter` → `bpf_compile` tools or `tcpdump -ddd`

## Limitations and considerations
- BPF bytecodes are non-trivial to write manually; use `tcpdump -ddd "filter expr"` to compile
- performance impact increases with bytecode complexity
- classic BPF only (not eBPF)

## Relations with other extensions
- pairs well with: `LOG`, `DROP`

## Official reference
- `iptables-extensions(8)`: section `bpf`

# Reference: osf

## Type
- `match`

## Purpose
Perform passive OS fingerprinting by matching TCP SYN packets against a signature database of known operating system TCP stack behaviors.

## Scope
- Tool: `iptables` / `ip6tables`
- Common protocols: `tcp`

## Basic syntax
```bash
iptables -A INPUT -p tcp --syn -m osf --genre Linux -j LOG --log-prefix "OSF-LINUX "
```

## Available options / matches
- `--genre string` — OS genre/name to match (case-insensitive)
- `--ttl value` — 0: use packet TTL; 1: accept range within ±5; 2: ignore TTL
- `--log level` — logging verbosity (0-3)

## Use cases by purpose
- `observability`
- `access-control`
- `hardening`

## Command examples
```bash
# Log Linux hosts on SSH
iptables -A INPUT -p tcp --dport 22 -m osf --genre Linux -j LOG --log-prefix "SSH-LINUX "
# Block Windows hosts from accessing service
iptables -A INPUT -p tcp --dport 8080 -m osf --genre "Windows" -j DROP
```

## Dependencies
- requires nf_osf kernel module
- requires signature database at `/etc/p0f.fp` or equivalent path
- only examines TCP SYN packets, so connection must not be established yet

## Limitations and considerations
- fingerprinting is heuristic and can be spoofed
- signature database must be kept current
- may require `--ttl 1` for NAT scenarios where TTL is modified

## Relations with other extensions
- pairs well with: `conntrack` (NEW state), `LOG`

## Official reference
- `iptables-extensions(8)`: section `osf`

# Reference: u32

## Type
- `match`

## Purpose
Match packets by testing arbitrary 32-bit values at specific byte offsets within the packet, supporting complex multi-field boolean expressions via a mini-language.

## Scope
- Tool: `iptables` / `ip6tables`
- Common protocols: any

## Basic syntax
```bash
iptables -A INPUT -m u32 --u32 "0>>22&0x3C@12>>26&0x3F=0x16" -j ACCEPT
```

## Available options / matches
- `--u32 expression` — u32 boolean expression in mini-language

## Use cases by purpose
- `deep-inspection`
- `custom-protocol`
- `hardening`

## Command examples
```bash
# Match TCP SYN packets by inspecting flags byte manually
iptables -A INPUT -p tcp -m u32 --u32 "0>>22&0x3C@13=0x02" -j LOG --log-prefix "U32-SYN "

# Match specific payload byte sequence starting at TCP data offset
iptables -A FORWARD -m u32 --u32 "0>>22&0x3C@4=0x47455420" -j DROP
```

## Dependencies
- requires `xt_u32` kernel module

## Limitations and considerations
- the u32 mini-language has steep learning curve; expression errors cause rule rejection at load time
- performance is lower than protocol-specific matches; use sparingly
- cannot span packet boundaries or handle variable-length headers without careful offset calculation

## Relations with other extensions
- supplements: `bpf` (bpf is often preferred for new deployments)

## Official reference
- `iptables-extensions(8)`: section `u32`
